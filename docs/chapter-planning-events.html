每条事件的闭合包

每条事件都带 run_id、step_id、attempt_id、input_revision、protocol_version=2、request_fingerprint、destination_fingerprint、execution_fingerprint，并逐项比较冻结预期值；另带 event_version=1、连续 seq 和目标 chapter_number。

ID为1–128字符ASCII认证无关标识；三个指纹为64位小写十六进制。request_fingerprint绑定执行目标、operation与模型参数，不能证明输入全文未变；目标章号单独比较，其他输入仍依赖现有冻结、revision与来源复验。

type额外字段含义
started无策划计算已接受，不含frozen_context，不表示保存或批准
progressnode / visit / status / elapsed_ms真实节点观察事件
doneresult / metrics完整候选，仍需正常EOF和本地保存
errorcode / message / status终止错误，可发生在started之前

所有帧、result、issues、任务、场景、metrics字段闭合。progress只允许四个固定节点；未知State、凭据、档案、metadata、原始provider body字段拒绝。error.code为1–80个ASCII字符，status为400–599，message最多500个Unicode码点；服务端必须经既有安全错误映射生成文案，纯类型校验不能证明自由字符串无敏感内容。

安全整数按数值语义验证：1与1.0等价，范围不超过2^53−1；布尔值不能冒充数字。elapsed_ms必须有限、非负且在同一安全范围内，不接受NaN/Infinity。

顺序、visit与观察耗时

started(seq=1)
  context_pack #1 started → finished
  initial_proposal #1 started → finished
  validate #1 started → finished
    ├ done(draft_ready)
    └ repair_once #1 started → finished
        validate #2 started → finished
          done(draft_ready 或 needs_user_decision)

任意非终态位置可用error终止；节点failed之后只允许error。
done/error之后不能再出现任何事件。

seq覆盖started、全部progress、done和error，从1连续递增；最多32条progress，因此包级seq上限34。当前固定图正常路径6条progress，修订路径10条。节点开始和结束配对，禁止跳过、重复、第三次修订或同时运行多个节点；仅validate允许visit=2。

elapsed_ms是服务端观察事件的累计时间，progress之间不回退，done.metrics.elapsed_ms也不小于最后progress；不是精准节点执行耗时。阶段二须使用共同monotonic起点，不能通过每节点重新计时满足字段。节点finished只说明节点执行结束，不说明规则通过或作者批准。

完整结果与EOF边界

done.result复用chapter-planning-v1的十个字段：graph_version、chapter_number、status、task_payload、scene_proposal、issues、repair_count、nodes、excluded_records、warnings。任务与场景仅保留编辑字段，不能伪造ID/revision/approval/binding。

nodes必须等于流中已完成节点路径，repair_count与有无修订一致。draft_ready必须有任务和场景且issues为空；needs_user_decision必须经历一次修订并有issues，可保留结构合法但有领域问题的候选给作者处理。契约不重新判断自由文本正确性。

metrics必须有operation=plan_chapter、protocol_version=2和elapsed_ms；已知token计数/首段与完成耗时可缺或null。call_count/repair_used可缺，存在时必须分别对应路径的1或2次调用、是否修订。禁止在metrics夹带原始provider响应。

只有完整done加正常流结束，调用finish()才得到候选。提前EOF、error、非法尾行、终态后追加事件都不能应用结果。得到候选后还要现有事务保存成功，才能称“结果已保存”；之后的任务/场景批准仍是独立作者操作。遇非法帧应终止请求并弃用当前校验实例。

参数解析/权限等HTTP前置错误仍可返回非2xx JSON，不属于成功NDJSON响应。error-before-started描述的是已进入流响应后的终止事件，不保证断开客户端仍能收到终止文案。

后端执行与浏览器责任

后端只运行一次图，内部tasks/values严格投影，保留新Context与禁追踪。180秒计算deadline从参数解析通过并获得admission起算，覆盖图与ASGI发送；解析独立限时。取消后等待上游清理，再释放槽位一次。截止或断连时可能来不及发送error，客户端必须把缺完整终态视为结果未知。

浏览器使用fatal UTF-8增量解析与闭合FSM；每帧先检查身份和合并AbortSignal。190秒客户端限时覆盖fetch、读取、连接检查与异步回调；onProgress的active参数包含调用方取消、连接撤销和内部超时，实际同步事务内也检查active。progress保存检查当前attempt/status、CAS和guard，bumpRevision=false。

轨迹只保留当前attempt的六个白名单字段，不写正文partial/reasoning、不触发正文前章锁、不批准任务或场景。手动重试新attempt清空轨迹，旧attempt_history不增加轨迹历史。非法轨迹或诊断旗标安全清洗并警告，正式结果与秘密字段检查保持；旧记录没有trace仍可恢复。界面独立显示节点执行与作者审核，运行中断不伪造节点完成。

纯校验器自身不读取网络或保存项目；computePlanningStream和localWorkflow分别负责读取与事务。单帧/残余buffer最多1,048,576个UTF-16码元，总响应最多2MiB。后端以真实ASGI mock覆盖发送阻塞、断连和清理，前端以真实Edge分块HTTP/IndexedDB/WebLocks验收；后端只在内部正常EOF后发送done，不再次运行图取结果。
